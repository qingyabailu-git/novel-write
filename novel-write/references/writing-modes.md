# Writing modes and contracts

## Quick mode

Use for short drafts, brainstorming, or a user who explicitly wants speed.

1. Read only the context needed for the requested fragment.
2. Write directly.
3. Perform a private check for obvious contradictions and unmet user requirements.
4. Do not start a reviewer chain.
5. Do not persist state unless the user asked for a file or a substantive chapter was explicitly requested.

## Standard mode

Use for an ordinary scene or chapter.

1. Read CREATOR.md, the relevant outline, progress, character state, chapter group, recent prose, and relevant lore.
2. Draft the requested scope.
3. Perform a read-only review across continuity, character logic, plot logic, pacing, prose, dialogue, style, and user requirements.
   At minimum, verify the scene opening has enough event context, every important action has a clear actor and object state, dialogue responds to the live exchange, limited-viewpoint knowledge is respected, and the ending points to a concrete next action or question.
4. Repair only real issues and preserve strong material.
5. Write the final chapter if requested.
6. Generate state updates from the final text and read them back.

## Heavy mode

Use for key scenes, multiple chapters, complex arcs, or high-risk continuity.

1. Build a Context Plan.
2. Draft against that plan.
3. Return structured review findings with severity and repair instructions.
4. Apply only necessary blocker and major repairs.
5. Run a Final Gate against the user request, Context Plan, canon, and style.
6. Check that suspense reveals the anomaly or result before its cause when the scene depends on concealment, and that equipment, objects, time, distance, and physical condition remain possible.
7. Generate progress, character-state, world-state, and foreshadowing patches from the final text only; planned beats that did not occur remain plans.
8. Persist and verify the final files.

## File safety

Use a full write for a new chapter or a complete rewrite. Use a precise edit for a local change. Always check the write result and read back the changed file. Never report success based only on an attempted tool call.
