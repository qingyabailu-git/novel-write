# Novel write

面向文件化小说项目的 ChatGPT/Codex skill 套件。

> English documentation: [README.md](README.md)

## 这是什么

Novel write 将小说创作拆分为可复用、可审查、可恢复的阶段：素材导入、项目初始化、长期设定管理、长期大纲、短期章节组规划、正文创作、章节续写、定向改稿、质量审查和文风管理。

这套 skills 适用于将权威创作资料保存在项目目录中的小说。它把正文、稳定设定、即时状态、未来计划和审查报告分开，确保后续写作依据实际发生的事件，而不是只依据旧摘要或计划。

只要某次写入可能建立正式设定、改变故事方向或创作重要正文，流程就会先确认再写入。系统区分已确认事实、候选内容、未来计划、推断和待决事项。审查 skill 始终只读；修复必须在获得授权后由独立改稿步骤执行。

## 包含的 Skills

| Skill | 用途 |
| --- | --- |
| novel-workflow | 统筹文件化小说的完整创作流程。 |
| novel-project-init | 创建或修复项目规范与文件结构。 |
| novel-lore | 管理稳定的人物、地点、规则、势力、能力和物品设定。 |
| novel-outline | 创建和修改长期故事结构。 |
| novel-chapter-plan | 规划接下来一组短期章节。 |
| novel-write | 按合适强度创作片段、场景或章节。 |
| novel-continue | 从实际最新正文和当前状态继续写作。 |
| novel-rewrite | 在保留连续性的前提下定向改稿。 |
| novel-review | 执行只读、带证据的质量门禁。 |
| novel-import | 预览并整理 TXT 或 Markdown 素材。 |
| novel-style | 定义可复用的文风规则，不保存剧情事实。 |

## 包结构

每个 skill 目录在适用时包含以下组件：

~~~text
novel-*/
├── SKILL.md                 # 主指令
├── agents/openai.yaml       # 界面元数据
├── references/              # 可复用的参考契约与格式
└── scripts/                 # 本地辅助脚本
~~~

根目录清单为 novel-write.json，记录包名、显示名称、版本、包含的 skills、排除功能和版本说明。

## 设计原则

### 1. 文件化连续性

实际正文是事件是否发生的主要证据。进度、人物状态、长期设定、长期大纲和章节组各自负责不同内容，不能互相静默替代。

### 2. 写入正式事实前先确认

导入预览、项目初始化、结构方案和大范围文风修改在写入前先展示。未确认的候选内容和未来计划必须保持明确标记。

### 3. 追踪到动作层

审查和写作复核会追踪时间、地点、视角人物知识、身体状态、动作主体、物品位置、设备操作流程和现实规则。

### 4. 对白必须承受现场压力

每个问题和回答都应回应上一动作、上一条信息或真实意图。人物回避时，应通过动作、距离、停顿或限知视角下的判断体现，而不是无解释地跳到别的话题。

### 5. 场景开合要具体

开头先交代读者理解事件所必需的最小场景信息。悬念可以先呈现异常或结果，再揭示原因。结尾应指向具体的下一步行动、选择、发现或可回答问题。

### 6. 连载节奏可以调整

对于多线连载作品，可以将活跃关系线标记为主线、稳定线或探索线，用来发现停滞和连续低影响章节。这些是编辑观察工具，不是适用于所有题材的硬性频率公式。

## 典型流程

~~~text
素材或已有项目
        ↓
导入预览或项目检查
        ↓
确认项目规范与文风
        ↓
长期大纲
        ↓
短期章节组
        ↓
写作或续写
        ↓
只读审查
        ↓
授权改稿并同步状态
~~~

总流程 skill 可以在内部推进这些阶段，不要求用户手动选择每个底层 skill。但涉及建立正式设定、改变故事方向或写入重要内容时，仍会在必要节点暂停确认。

## 审查与质量门禁

审查流程检查：

- 用户要求、受保护内容和内容边界；
- 时间、地点、顺序、物品、伤势、知识边界和因果；
- 人物动机、决策压力、声线和行为；
- 动作主体、对象、持有关系、设备状态和现实可行性；
- 对白回应关系和有意义的动作；
- 节奏、升级、场景开头、悬念顺序和具体钩子；
- 含糊解释、重复句式和可观察的 AI 式表达习惯。

审查会返回通过或不通过结论、剩余阻塞项、建议项、证据、违反规则、影响和修复指令。审查 skill 不直接修改项目。

## 辅助脚本

### split_novel.py

按章节标题预览或拆分 UTF-8 TXT/Markdown 文件。支持 dry-run 和 JSON 输出，会在报告中保留首章标题前的未分配文本，并且只写入用户明确指定的输出目录。

### check_novel_project.py

对文件化小说项目执行保守的本地结构和 UTF-8 检查，报告缺失项目文件、无法读取的文本、空章节和替换字符。

两个脚本都只在本地运行，不发起网络请求。

## 安装

1. 将需要的 novel-* 目录复制到兼容 Codex 的 skill 目录。
2. 保留每个目录中的 SKILL.md。
3. 如果宿主支持元数据和参考资源，请同时保留 agents/openai.yaml 与 references/。
4. 保留 scripts/，以便执行导入预览和结构检查。
5. 需要完整流程时从 novel-workflow 开始，也可以直接调用单个专项 skill。

## 范围与隐私

本包只包含 skill 指令、可复用参考文件、本地辅助脚本、界面元数据和包元数据，不包含：

- 小说正文或章节文件；
- 人物档案、设定库或世界观资料；
- 私人项目路径、作者笔记、浏览器数据、凭据或 API 密钥；
- 插图、封面、互动图像、互动故事、故事导演或定时自动化执行功能。

使用这些 skills 时，应以选定项目和用户当前明确提供的材料作为事实边界。不要用无关项目、旧摘要或未经确认的推测补全缺失信息。
